API keys authenticate requests to the Quillstack API at https://api.quillstack.com/v2. You create and manage keys under Settings > Integrations > API in the web app. Each key is shown in full only once, at the moment of creation, so store it securely before closing the dialog.

## Before you start

Only workspace Admins and Owners can create API keys. Viewers and Editors do not have access to Settings > Integrations. Check your role under Settings > Members if the API section does not appear.

Your plan determines how many active keys you can have and how long each key remains valid:

| Plan | Maximum active keys | Expiry |
|------|---------------------|--------|
| Free | 1 | 30 days |
| Team | 10 | 90 days |
| Business | 50 | 365 days |

Keys must be rotated before they expire. After expiry, API requests return error QS-1042 and the key cannot be reactivated. Plan the rotation schedule now to avoid interruptions.

## Steps

1. Sign in to app.quillstack.com and open the workspace where you need API access.
2. Go to **Settings > Integrations > API**.
3. Click **Create API key**.
4. Enter a descriptive name for the key, such as "Production server" or "CI pipeline". This name appears in the key list and audit logs.
5. Click **Create**.
6. Copy the full key from the dialog. API keys begin with the prefix `qs_live_` followed by a random string. This is the only time you will see the complete key.
7. Store the key in a secure location: a password manager, secrets vault, or environment variable on your server. Do not commit it to version control.
8. Click **Done** to close the dialog.

The key is now active and appears in the list with its name, creation date, and expiry date. Use it in the `Authorization` header of every API request:

```
Authorization: Bearer qs_live_3x4mpl3k3y...
```

## Limits and expiry

If you reach the maximum number of active keys for your plan, the **Create API key** button is disabled. Revoke an unused key or upgrade your plan to create more.

Every key has an expiry date shown in the key list. The API continues to accept requests until 23:59:59 UTC on the expiry date. After that, requests fail with error QS-1042. Rotate keys before expiry by creating a replacement, updating your application to use the new key, and revoking the old one.

On the Business plan with a 365-day expiry, schedule rotation at least 14 days before the expiry date. This gives you time to coordinate changes across multiple services and test the new key in staging.

## Troubleshooting

**The key list is empty and I cannot create a key**  
Your workspace may be in read-only mode after a failed payment. Update the payment method under Settings > Billing to restore full access, then create the key.

**I closed the dialog without copying the key**  
The key cannot be retrieved. Revoke it from the key list and create a new one. API keys are shown in full only once for security reasons.

**My application returns QS-1003: missing Authorization header**  
Check that your code sends the `Authorization` header on every request. The header format is `Authorization: Bearer qs_live_...` with a space after `Bearer` and no extra quotes or brackets.

**I need more than 50 keys on Business**  
Contact support with your use case. The 50-key limit prevents accidental key sprawl and simplifies rotation. Most integrations use fewer than 10 keys, with one key per environment or service.

**Can I extend the expiry date of an existing key?**  
No. Expiry dates are fixed when the key is created and cannot be changed. Rotate the key by creating a new one before the current key expires.
