Every task in Quillstack has a unique key, a status that tracks where it sits in your workflow, and a set of properties you can customize. Understanding how task keys work is essential if you use the GitHub integration, and knowing how to configure statuses lets you model your team's actual process.

## Before you start

You need at least Editor permissions to create or update tasks. Task keys are assigned automatically when you create a task and cannot be changed. Each project has its own key prefix, which you set when you create the project.

## How task keys work

A task key has the form PROJECTKEY-NUMBER, for example DOCS-142. The project key is a short uppercase string you choose when you create the project, and the number increments for each new task in that project. The first task in a project is always PROJECTKEY-1, the second is PROJECTKEY-2, and so on. Task keys appear in the task title bar, in search results, and in the URL when you open a task.

The GitHub integration links a pull request to a task when the PR title or branch name contains the task key, which has the form PROJECTKEY-NUMBER, for example DOCS-142. When the link is established, the task shows the PR status and a direct link to the pull request.

## Statuses and workflows

Every task has a status that describes where it is in your workflow. The default statuses are To Do, In Progress, and Done, but you can add, rename, or remove statuses to match your process. Statuses are configured per project under Projects > [project name] > Settings > Statuses.

Each status belongs to one of three categories:

| Category | Meaning | Effect |
|----------|---------|--------|
| Open | Work has not started or is in progress | Task counts toward the 5,000 open task limit |
| Done | Work is complete | Task is excluded from the open task count |
| Archived | Task is closed without completion | Task is excluded from the open task count |

You can have as many statuses as you need in each category. When you mark a task with a Done or Archived status, it no longer counts against the project's open task limit.

## Steps

### Create a custom status

1. Go to Projects and open the project you want to configure.
2. Click Settings > Statuses.
3. Click Add status.
4. Enter a name and choose a category (Open, Done, or Archived).
5. Click Save.

The new status appears in the status dropdown for every task in that project.

### Change the default status for new tasks

1. Go to Projects > [project name] > Settings > Statuses.
2. Find the status you want to use as the default.
3. Click the three-dot menu and select Set as default.
4. All new tasks in this project will start with that status.

## Limits

A project can hold at most 5,000 open tasks. Tasks with a Done or Archived status do not count toward this limit. If you reach 5,000 open tasks, you must mark some tasks as done or archived before you can create new ones. Archived projects are read-only and can be restored by an Admin or Owner from Projects > Archived.

## Troubleshooting

**The GitHub integration does not link my pull request to a task.** The PR title or branch name must contain the exact task key, including the hyphen and number. DOCS142 will not work; it must be DOCS-142. See the GitHub integration troubleshooting article for more details.

**I cannot create a new task.** You may have reached the 5,000 open task limit. Check the project dashboard for the open task count, and mark completed tasks as Done to free up capacity.

**A task key skipped a number.** Task numbers increment even if a task creation fails or is canceled. Gaps in the sequence are normal and do not indicate a problem.
