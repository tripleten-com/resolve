Every webhook payload sent by Quillstack includes a cryptographic signature that you can use to verify the request came from Quillstack and was not tampered with. Verifying signatures is essential for security; without it, anyone could send fake webhook payloads to your endpoint. This article explains how to verify the signature in your code.

## Before you start

Webhook payloads are signed with HMAC-SHA256; the hex signature is sent in the X-Quillstack-Signature header and signing secrets begin with whsec_. You receive the signing secret when you create a webhook endpoint under Settings > Integrations > Webhooks. The secret is shown only once, so store it securely. If you lose the secret, you must delete the webhook and create a new one.

## Steps

Follow these steps to verify a webhook signature:

1. Read the raw request body as a string or bytes. Do not parse it as JSON before verification.
2. Read the X-Quillstack-Signature header from the incoming request.
3. Compute the HMAC-SHA256 hash of the raw body using your signing secret as the key.
4. Convert the computed hash to a hexadecimal string.
5. Compare the computed signature to the value in the X-Quillstack-Signature header. If they match, the payload is authentic.
6. Reject the request if the signatures do not match.

Here is an example in Python using the hmac library:

```python
import hmac
import hashlib

def verify_signature(payload_body, signature_header, secret):
    expected_signature = hmac.new(
        secret.encode('utf-8'),
        payload_body.encode('utf-8'),
        hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected_signature, signature_header)

# In your webhook handler
payload = request.get_data(as_text=True)
signature = request.headers.get('X-Quillstack-Signature')
secret = 'whsec_abc123def456ghi789'

if not verify_signature(payload, signature, secret):
    return 'Invalid signature', 401
```

Use a constant-time comparison function like hmac.compare_digest to prevent timing attacks.

## How the signature is computed

Quillstack computes the signature by taking the raw JSON payload body and signing it with HMAC-SHA256 using your webhook secret as the key. The result is converted to a lowercase hexadecimal string and sent in the X-Quillstack-Signature header. You must perform the same computation on your server and compare the result to the header value.

The signature is computed over the exact bytes of the request body. If you parse the JSON and re-serialize it, the signature will not match because JSON serialization is not deterministic. Always verify the signature before parsing the payload.

## Common mistakes

The most common mistake is parsing the request body as JSON before verifying the signature. This changes the byte representation and causes the signature check to fail. Always read the raw body first, verify the signature, and only then parse the JSON.

Another common mistake is using the wrong encoding when computing the HMAC. The secret and payload must both be encoded as UTF-8 bytes before passing them to the HMAC function. If you use a different encoding or pass strings instead of bytes, the computed signature will not match.

The table below lists common issues and solutions:

| Issue | Cause | Solution |
|-------|-------|----------|
| Signature mismatch | Parsed JSON before verifying | Verify raw body first |
| Signature mismatch | Wrong encoding | Use UTF-8 for secret and payload |
| Missing header | Not reading X-Quillstack-Signature | Check header name spelling |

## Signature expiry

Webhook signatures do not expire, but you should reject payloads that are too old to prevent replay attacks. Check the timestamp field in the payload and reject any request where the timestamp is more than 5 minutes in the past. This ensures that an attacker cannot capture a valid payload and replay it later.

## Troubleshooting

If signature verification always fails, print the raw request body and the computed signature to debug. Compare the raw body you received to the body you are signing. They must be identical, byte for byte. If they differ, check that your web framework is not modifying the request body before you read it.

If the X-Quillstack-Signature header is missing, verify that you are reading the correct header name. HTTP headers are case-insensitive, but some frameworks normalize them. If your framework lowercases headers, look for x-quillstack-signature instead.

If you rotated your signing secret but forgot to update your verification code, signature checks will fail. Make sure your server is using the current secret for the webhook endpoint.
