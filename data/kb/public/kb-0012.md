Projects in Quillstack let you organize work into tasks, track progress, and collaborate with your team. Each project can hold up to 5,000 open tasks, and every task gets a unique key you can reference in pull requests, pages, and discussions.

## Before you start

You need Editor, Admin, or Owner permissions to create a project. Viewers can see projects and tasks but cannot create or edit them. Check your role under Settings > Members if you are not sure.

Each task in a project is assigned a key in the format PROJECTKEY-NUMBER, such as DOCS-142. These keys are unique within your workspace and are used to link tasks to GitHub pull requests, mention tasks in pages, and track work across tools.

## Steps

1. Click **Projects** in the sidebar and then click **New project**.
2. Enter a project name and a short project key (2-10 uppercase letters, such as DOCS or ENG).
3. Choose a default view: **Board**, **List**, or **Timeline**.
4. Click **Create project** to finish.

Once the project is created, you can start adding tasks. Click **New task** in the project view, enter a title, and press Enter. The task is assigned the next available task key automatically, starting with PROJECTKEY-1.

### Add details to a task

1. Click on a task to open it.
2. Add a description, assignee, due date, labels, or attachments using the fields in the task detail view.
3. Change the task status by clicking the status dropdown and selecting a new status.
4. Close the task detail view to return to the project.

Tasks remain in the project until you mark them as complete or archive the project. Completed tasks stay visible in the project by default but can be hidden using the view filters.

## Limits

| Limit                     | Value                                      |
|---------------------------|--------------------------------------------|
| Open tasks per project    | 5,000                                      |
| Task key format           | PROJECTKEY-NUMBER (e.g., DOCS-142)         |
| Archived project access   | Read-only, restorable by Admin or Owner    |

If a project reaches 5,000 open tasks, you must complete or delete some tasks before adding new ones. Archived projects are read-only and can be restored by an Admin or Owner from Projects > Archived.

## How GitHub linking works

When you connect the GitHub integration, pull requests automatically link to tasks if the PR title or branch name contains a task key. For example, a branch named `fix-docs-142` or a PR titled `Update API docs (DOCS-142)` will link to task DOCS-142. The link appears in the task detail view under Activity, and the task status updates when the PR is merged.

## Troubleshooting

**I cannot create a project.** You need Editor, Admin, or Owner permissions. Viewers cannot create projects. Ask a workspace Admin to promote your role if you need to create projects.

**I reached the 5,000 open task limit.** Complete tasks you no longer need or archive them. Go through the project and mark finished tasks as complete, or archive the entire project if the work is done and create a new project for ongoing tasks.

**Task keys are not linking to GitHub pull requests.** Make sure the GitHub integration is installed and the PR title or branch name includes the exact task key, including the project prefix and number. See the troubleshooting guide for more details.

**Can I change a project key after creating the project?** No. Project keys are permanent and cannot be changed once the project is created. Task keys depend on the project key, so changing it would break links to those tasks in pull requests, pages, and other references.
