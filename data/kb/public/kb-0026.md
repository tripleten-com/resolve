After you configure SAML or OIDC single sign-on, you can require every member to use it by setting `sso.enforce` to true. This blocks password sign-in for everyone except workspace Owners, who keep password access as a recovery path in case the SSO connection breaks. Enforcing SSO is optional and available only on the Business plan.

## Before you start

You must finish setting up SAML or OIDC and test that at least one member can sign in through your identity provider before you enforce SSO. If you enable enforcement without a working SSO connection, members who are not Owners will be locked out and unable to sign in.

Owners can always sign in with a password even when `sso.enforce` is true. This ensures that you can fix SSO configuration problems or disable enforcement if your identity provider goes down. Other roles (Admin, Editor, Viewer) lose password sign-in completely once enforcement is active.

## Steps

1. Sign in to app.quillstack.com as an Owner and go to Settings > Security > Single sign-on.
2. Confirm that the SSO connection is working by testing a sign-in in a private browser window.
3. Scroll to the Enforce SSO section and check the box labeled "Require SSO for all members (Owners excepted)".
4. Click Save settings.
5. Notify your workspace members that password sign-in is now disabled and they must use the SSO button on the sign-in page.

If you later need to disable enforcement, uncheck the box in step 3 and save. Members will be able to sign in with passwords again immediately.

## How enforcement works

When `sso.enforce` is set to true, the Quillstack sign-in page hides the password field for Admins, Editors, and Viewers. They see only the "Sign in with SSO" button. Owners still see both options and can choose either password or SSO. If a non-Owner tries to sign in by calling the password authentication API directly, the request is rejected.

Enforcement does not affect existing sessions. A member who is already signed in stays signed in until the session expires (30 days of inactivity on web, 90 days on mobile). The next time they sign in, they must use SSO.

Two-factor authentication is not required when signing in through SSO, because your identity provider handles authentication. If you have enabled 2FA for the workspace, it applies only to password sign-ins, which means only Owners see 2FA prompts after enforcement is enabled.

## Configuration reference

| Setting | Type | Description |
|---------|------|-------------|
| `sso.enforce` | boolean | Set to `true` to block password sign-in for non-Owners; set to `false` (default) to allow both SSO and password sign-in |
| `sso.entity_id` | string | SAML entity ID from your identity provider |
| `sso.sign_in_url` | string | SAML single sign-on URL from your identity provider |
| `sso.certificate` | string | X.509 certificate (PEM format) from your identity provider |

The ACS URL you provide to your SAML identity provider is `https://app.quillstack.com/sso/saml/acs`. For OIDC, the redirect URI is `https://app.quillstack.com/sso/oidc/callback`.

## Troubleshooting

If a non-Owner reports being locked out after you enable enforcement, verify that the SSO connection is working by signing in yourself through SSO (not with your Owner password). If SSO is broken, disable enforcement temporarily, fix the connection, test it, then re-enable enforcement.

If Owners cannot sign in with a password even though enforcement should allow it, check that their role is actually Owner and not Admin. Only the Owner role bypasses enforcement. You can verify roles under Settings > Members.

If you need to disable SSO entirely and revert to password-only sign-in, set `sso.enforce` to false and then delete the SSO configuration (clear `sso.entity_id`, `sso.sign_in_url`, and `sso.certificate` for SAML, or `sso.client_id`, `sso.client_secret`, and `sso.issuer_url` for OIDC). Members will need to reset their passwords if they have not used them in a long time.
