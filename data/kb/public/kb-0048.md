List endpoints in the Quillstack API return paginated results using cursor-based pagination. This prevents timeouts and memory issues when working with large datasets. This article explains how pagination works and how to retrieve all pages in a result set.

## Before you start

List endpoints use cursor pagination: page_size defaults to 50 and is capped at 200, and the response field next_cursor is null on the last page. You control the page size by passing a page_size query parameter. To retrieve the next page, pass the next_cursor value from the previous response as the cursor query parameter. Cursor values are opaque strings; do not attempt to parse or modify them.

## Steps

Follow these steps to paginate through a list endpoint:

1. Make the first request without a cursor parameter. Optionally include page_size to set the number of results per page.
2. Read the next_cursor field from the response. If it is null, you have reached the last page.
3. If next_cursor is not null, make another request with cursor set to that value.
4. Repeat steps 2 and 3 until next_cursor is null.

Here is an example that lists all pages in a workspace:

```bash
# First request
curl -X GET "https://api.quillstack.com/v2/pages?page_size=100" \
  -H "Authorization: Bearer qs_live_abc123"

# Response includes next_cursor
# {
#   "data": [ ... ],
#   "next_cursor": "eyJpZCI6MTIzNDU2fQ=="
# }

# Second request with cursor
curl -X GET "https://api.quillstack.com/v2/pages?page_size=100&cursor=eyJpZCI6MTIzNDU2fQ==" \
  -H "Authorization: Bearer qs_live_abc123"
```

Continue until next_cursor is null in the response.

## Response structure

Every list endpoint returns a JSON object with a data array and a next_cursor field. The data array contains the results for the current page. The next_cursor field is either a string (if more results exist) or null (if this is the last page). Here is an example response:

```json
{
  "data": [
    {"id": "page_001", "title": "Getting started"},
    {"id": "page_002", "title": "API reference"}
  ],
  "next_cursor": "eyJpZCI6MTIzNDU2fQ=="
}
```

When you reach the last page, the response looks like this:

```json
{
  "data": [
    {"id": "page_099", "title": "Final page"}
  ],
  "next_cursor": null
}
```

## Page size limits

The page_size parameter defaults to 50 if you do not specify it. The maximum value is 200. If you pass a value greater than 200, the API uses 200 instead. Smaller page sizes mean more requests but faster individual responses. Larger page sizes mean fewer requests but slower responses. Choose a page size based on your use case. For real-time syncing, use a smaller page size. For bulk exports, use 200.

| Page size | Requests for 1000 results | Use case |
|-----------|---------------------------|----------|
| 50 (default) | 20 | General purpose |
| 100 | 10 | Balanced |
| 200 (maximum) | 5 | Bulk operations |

## Cursor expiry and stability

Cursors do not expire, but they may become invalid if the underlying data changes significantly. If a cursor becomes invalid, the API returns an error and you must start from the beginning. This is rare and usually only happens if you hold a cursor for many hours while the dataset is being modified. For most use cases, you can paginate through results immediately and the cursor will remain valid.

Do not assume that results are sorted in any particular order unless the endpoint documentation specifies a sort order. The cursor encodes the position in the result set, but the order may change between requests if new items are added or existing items are modified.

## Troubleshooting

If the next_cursor field is missing from the response, check that you are calling a list endpoint and not a single-resource endpoint. Single-resource endpoints like GET /v2/pages/:id do not return pagination fields. If next_cursor is always null even when you expect more results, verify that your API key has access to the workspace and that the resources exist.

If you receive an error when using a cursor, discard the cursor and start from the first page again. Cursors are not guaranteed to remain valid indefinitely, especially if you pause between requests for an extended period.
