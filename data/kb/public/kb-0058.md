After you connect Slack to Quillstack, you can route notifications for specific events to different Slack channels. For example, send page updates to your documentation channel and task completions to your engineering channel. You configure routing under Settings > Integrations > Slack, and each workspace can post to at most 20 Slack channels.

## Before you start

The Slack integration must be connected before you can configure event routing. If you have not connected Slack yet, follow the steps in the article linked below. You need Admin or Owner permissions in your Quillstack workspace to change integration settings.

## Steps

1. In Quillstack, go to **Settings > Integrations > Slack**.
2. Under **Event routing**, click **Add rule**.
3. In the **Event** dropdown, select the type of event you want to route. Available events are listed in the table below.
4. In the **Channel** dropdown, select the Slack channel where notifications for this event should be posted.
5. Click **Save rule**.
6. Repeat steps 2–5 for each event type you want to route to a specific channel.

Any event without a routing rule is sent to the default channel you configured when you connected the integration.

## Available event types

You can route notifications for these Quillstack events:

| Event type | When it triggers |
|------------|------------------|
| `page.created` | A new page is created in any workspace |
| `page.updated` | An existing page is edited |
| `page.deleted` | A page is moved to Trash |
| `task.created` | A new task is added to any project |
| `task.updated` | A task's title, assignee, status, or other field is changed |
| `task.completed` | A task is marked as complete |
| `project.archived` | A project is archived |

Each event type can be routed to a different Slack channel, or multiple events can share the same channel. If you route an event to a channel and later delete the rule, that event returns to posting in the default channel.

## Remove a routing rule

To stop sending a specific event to a Slack channel:

1. Go to **Settings > Integrations > Slack > Event routing**.
2. Find the rule you want to remove and click **Delete** next to it.
3. Confirm by clicking **Delete rule**.

The event now posts to the default channel instead. Deleting a rule does not remove past messages from the Slack channel.

## Change the default channel

The default channel receives all events that do not have a routing rule. To change it:

1. Go to **Settings > Integrations > Slack**.
2. Under **Default channel**, select a new channel.
3. Click **Save**.

You can also set the default channel using the `slack.default_channel` configuration key:

```
slack.default_channel = #team-updates
```

This is the fallback for any event type you have not explicitly routed. If you remove all routing rules, every event goes to the default channel.

## Channel limit

A Quillstack workspace can post to at most 20 Slack channels. This limit includes the default channel and all channels used in event routing rules. If you try to add a 21st channel, you see an error. To work around this, remove routing rules for channels you no longer need or consolidate events into fewer channels. For example, route all task events to a single engineering channel instead of separate channels for `task.created`, `task.updated`, and `task.completed`.

## Troubleshooting

**I added a rule but messages still go to the default channel.** Check that the event type in your rule matches the events you expect to see. For example, if you route `task.created` but are looking for task completions, you need a separate rule for `task.completed`. Each event type requires its own rule.

**Slack says it cannot find the channel.** The Slack integration can only post to public channels and private channels where the Quillstack app has been invited. If the channel is private, open it in Slack, click the channel name, and select **Integrations > Add apps**. Search for Quillstack and add it.

**I reached the 20-channel limit.** Review your routing rules and remove channels you no longer use. If you need more flexibility, consider using webhooks to send events to a custom service that routes them to Slack. Webhooks are not subject to the 20-channel limit.

**Notifications are delayed by several minutes.** Slack notifications are sent in near real-time, but delays can occur during high traffic periods or if Slack's API is slow. If delays persist for more than 10 minutes, check the Quillstack status page or contact support.
