Webhooks let you receive real-time notifications when events occur in your Quillstack workspace. Instead of polling the API, your server receives an HTTP POST request whenever a page is created, a task is updated, or a project is archived. This article explains how to set up a webhook endpoint and configure which events you want to receive.

## Before you start

You need a publicly accessible HTTPS endpoint that can receive POST requests. Quillstack sends webhook payloads to this URL. Your endpoint must return an HTTP 2xx status code within 10 seconds to acknowledge receipt. Webhook payloads are signed with HMAC-SHA256; the hex signature is sent in the X-Quillstack-Signature header and signing secrets begin with whsec_. You should verify the signature on every incoming request to ensure the payload came from Quillstack.

## Steps

Follow these steps to create a webhook:

1. Sign in to app.quillstack.com and navigate to Settings > Integrations > Webhooks.
2. Click Add webhook endpoint.
3. Enter the URL where you want to receive webhook events. The URL must use HTTPS.
4. Select the event types you want to subscribe to. You can choose one or more events.
5. Click Create. The signing secret is displayed once; copy it and store it securely.
6. Test the endpoint by triggering an event in your workspace. For example, create a page to trigger a page.created event.

Your endpoint is now active and will receive POST requests for the selected event types.

## Event types

Webhook event types are page.created, page.updated, page.deleted, task.created, task.updated, task.completed, and project.archived. You can subscribe to any combination of these events. Each event type includes a payload with details about what changed. For example, task.completed includes the task ID, project key, and completion timestamp.

The table below lists all available event types:

| Event type | Triggered when |
|------------|----------------|
| page.created | A new page is created |
| page.updated | A page is edited or moved |
| page.deleted | A page is moved to Trash |
| task.created | A new task is added to a project |
| task.updated | A task is edited or moved |
| task.completed | A task status changes to completed |
| project.archived | A project is archived |

## Payload format

Every webhook payload is a JSON object with type, timestamp, and data fields. The type field indicates which event occurred. The timestamp field is an ISO 8601 timestamp showing when the event happened. The data field contains the resource that changed. Here is an example payload for a task.created event:

```json
{
  "type": "task.created",
  "timestamp": "2024-08-15T14:32:18Z",
  "data": {
    "id": "task_abc123",
    "key": "DOCS-142",
    "title": "Write API webhook guide",
    "project_id": "proj_xyz789",
    "status": "in_progress"
  }
}
```

The X-Quillstack-Signature header contains the HMAC-SHA256 hex signature of the raw payload body, signed with your webhook secret.

## Managing webhooks

You can edit or delete a webhook endpoint under Settings > Integrations > Webhooks. Click the endpoint in the list to view recent deliveries, including the HTTP status code and response time for each attempt. If an endpoint fails repeatedly, Quillstack disables it automatically and you must re-enable it manually after fixing the issue.

To rotate a signing secret, delete the existing webhook and create a new one. There is no way to regenerate a secret without creating a new webhook.

## Troubleshooting

If your endpoint is not receiving webhooks, check that the URL is publicly accessible and returns a 2xx status code. Test the endpoint with curl to confirm it responds correctly. If the endpoint was disabled due to failures, re-enable it under Settings > Integrations > Webhooks after fixing the underlying issue.

If you see webhook deliveries in the dashboard but your server is not processing them, verify that you are reading the request body correctly and that your signature verification logic matches the expected HMAC-SHA256 hex format. The signature is computed over the raw request body, not the parsed JSON.
