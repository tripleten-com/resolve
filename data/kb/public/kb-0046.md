API keys expire after a fixed period that depends on your Quillstack plan. When a key expires, requests using that key fail with error QS-1042. You must rotate the key before it expires to avoid interruptions to your integrations.

## Before you start

Check your plan to understand your key expiry period. API keys expire after 30 days on Free, 90 days on Team, and 365 days on Business, and must be rotated before they expire. You can see the creation date and expiry date for every key under Settings > Integrations > API keys. Plan ahead to rotate keys before they expire, especially if you have automated processes that run without manual oversight.

## Steps

Follow these steps to rotate an expiring key:

1. Sign in to app.quillstack.com and navigate to Settings > Integrations > API keys.
2. Click Create API key and give the new key a descriptive name.
3. Copy the new key immediately; it is shown in full only once.
4. Update your integration to use the new key. Test that it works before revoking the old key.
5. Once you confirm the new key works, revoke the old key by clicking Revoke next to it in the list.

If you wait until after a key expires, you must create a new key and update your integration immediately. There is no way to extend or renew an expired key.

## Error QS-1042: API key has expired

Error QS-1042 means the API key has expired. When you see this error, the key is no longer valid and you must create a new one. Requests using an expired key will always fail with this error. The response looks like this:

```json
{
  "code": "QS-1042",
  "message": "API key has expired",
  "request_id": "req_7j3k9m2n4p5q6r8s"
}
```

Create a new key under Settings > Integrations > API keys, update your integration, and test that requests succeed before you remove the expired key from your code.

## Error QS-1041: API key is invalid or revoked

Error QS-1041 means the API key is invalid or has been revoked. This happens when you revoke a key manually or if the key string is malformed. If you see this error, check that you are using the correct key and that it has not been revoked. If the key was revoked by mistake, you must create a new one; revoked keys cannot be restored.

## How to avoid expiry issues

Set a reminder to rotate your keys well before they expire. For example, if your keys expire after 90 days, set a reminder at 80 days. Many teams automate key rotation using a script that creates a new key, updates the environment variable or secrets manager, and revokes the old key. If you manage multiple keys, keep a spreadsheet or dashboard that tracks the expiry date for each one.

The table below shows expiry periods by plan:

| Plan | Key expiry | Recommended rotation |
|------|-----------|---------------------|
| Free | 30 days | Every 25 days |
| Team | 90 days | Every 80 days |
| Business | 365 days | Every 350 days |

## Troubleshooting

If you rotate a key but still see error QS-1042, confirm that your integration is using the new key and not a cached or hardcoded old key. Check environment variables, configuration files, and any secrets management tools. If you use a CI/CD pipeline, make sure the new key is stored in the pipeline secrets.

If you see error QS-1041 instead of QS-1042, the key may have been revoked or the key string is incorrect. Verify that the key begins with qs_live_ and that you copied the entire string when you created it. If the key is correct but the error persists, check that the workspace associated with the key still exists and is not in read-only mode.
