The audit log tracks security-relevant actions in your workspace, recording who did what and when. This article explains how to access the log, what events are recorded, and how to export the full history for compliance or investigation.

## Before you start

The audit log is Business-only, retained for 365 days, and exportable as CSV from Settings > Security > Audit log. If you downgrade from Business to Team or Free, the log becomes read-only immediately and all events are deleted after 30 days. Only Admins and Owners can view or export the audit log.

## Steps

1. Sign in at app.quillstack.com and go to **Settings > Security > Audit log**.
2. Use the search box to filter by user email, action type, or resource name.
3. Click any event row to expand it and view the full details, including the user's IP address and user agent.
4. Click **Export CSV** to download the entire log for the past 365 days.
5. The exported file includes columns for timestamp, user, action, resource type, resource ID, IP address, and user agent.

The audit log updates in real time. Events appear within 60 seconds of the action being performed.

## Recorded events

The audit log captures the following categories of events:

**Authentication and access**
- Sign-in (successful and failed)
- Sign-out
- Password reset
- Two-factor authentication enabled or disabled
- SSO configuration changed (sso.entity_id, sso.sign_in_url, sso.certificate, sso.enforce)
- API key created, rotated, or revoked
- Session expired or terminated

**Workspace and member management**
- Member invited or removed
- Role changed (Owner, Admin, Editor, Viewer)
- Workspace created or deleted
- Workspace settings changed (name, time zone, retention policies)
- Billing contact changed

**Content actions**
- Page created, updated, or deleted
- Page restored from Trash
- Page shared with public link (Share > Anyone with the link)
- Project created or archived
- Task created, updated, or completed
- File uploaded or deleted

**Security settings**
- Require 2FA enabled or disabled (Settings > Security > Require 2FA)
- IP allowlist updated (api.ip_allowlist)
- Webhook endpoint added, updated, or disabled
- Integration connected or disconnected (Slack, GitHub)

## Compliance and retention

The audit log is retained for 365 days. Events older than 365 days are automatically deleted and do not appear in exports. If your organization requires longer retention for compliance, export the log monthly and store the CSV files in your own archive.

Each event includes the following fields:

| Field | Description |
|-------|-------------|
| timestamp | ISO 8601 timestamp in UTC |
| user_email | Email of the user who performed the action |
| action | Action type (for example page.created, member.removed) |
| resource_type | Type of affected resource (page, task, project, workspace, member) |
| resource_id | Unique identifier of the affected resource |
| ip_address | IP address from which the action was performed |
| user_agent | Browser or API client that performed the action |

## Troubleshooting

**I do not see Settings > Security > Audit log.** The audit log is only available on the Business plan. Upgrade at Settings > Billing > Plan to enable it. The log starts recording events immediately after the upgrade.

**Events are missing from the log.** The log records only actions performed after the feature was enabled. If you upgraded to Business today, earlier events are not backfilled. Additionally, some automated system actions (for example scheduled exports or webhook retries) are not logged.

**The CSV export is empty.** Exports include only events from the past 365 days. If the workspace was created recently, the export may contain fewer rows. Check that you are signed in as an Admin or Owner—Editors and Viewers cannot access the audit log.

**Can I filter the log by date range?** The web interface does not support date filtering, but the CSV export includes a timestamp column. Import the CSV into a spreadsheet or database to filter by date.
