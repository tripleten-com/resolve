If your organization requires that API requests come only from known IP addresses, you can configure an allowlist on the Business plan. Requests from addresses outside the allowlist are rejected, adding a layer of defense against stolen or leaked API keys.

## Before you start

The IP allowlist for API keys is a Business-only setting, `api.ip_allowlist`, and accepts up to 20 CIDR ranges. You need Admin or Owner permissions to configure it under Settings > Security > API access. This setting applies to all API keys in the workspace; you cannot set different allowlists for individual keys.

## How it works

When `api.ip_allowlist` is enabled, every API request is checked against the list of allowed CIDR ranges. If the request originates from an IP address that does not match any range, the API returns HTTP 403 with error code QS-1014. The allowlist does not affect web app access or mobile app access, only requests to `https://api.quillstack.com/v2`.

## Steps

### Configure the IP allowlist

1. Sign in to app.quillstack.com and open Settings > Security > API access.
2. Under "IP allowlist", click **Add range**.
3. Enter a CIDR range (for example, `203.0.113.0/24` for a subnet or `203.0.113.42/32` for a single address).
4. Repeat for each range you want to allow, up to a maximum of 20 ranges.
5. Click **Save changes**.

All API requests from addresses outside these ranges are now rejected. Test your integration immediately to confirm it can still reach the API.

### Test the allowlist

After saving the allowlist, test an API request from an allowed address:

```bash
curl -H "Authorization: Bearer qs_live_..." \
     https://api.quillstack.com/v2/workspaces/me
```

If the request succeeds, the allowlist is working. If you receive a 403 error, verify that the CIDR range includes your server's public IP address.

## Limits

| Plan | IP allowlist available | Maximum ranges |
|------|------------------------|----------------|
| Free | No | — |
| Team | No | — |
| Business | Yes | 20 |

You can view your current IP address by visiting a service like `https://api.ipify.org` from the same server that makes API requests. Make sure to add the public IP address, not a private RFC 1918 address like `10.0.0.0/8` or `192.168.0.0/16`.

## Troubleshooting

**I am locked out after enabling the allowlist.** If you accidentally saved an allowlist that excludes your own server, you cannot make API requests to fix it. Sign in to app.quillstack.com, go to Settings > Security > API access, and update the allowlist to include your IP address or disable the allowlist temporarily.

**Can I allow requests from a VPN or proxy?** Yes. Add the VPN or proxy exit IP address to the allowlist. If your VPN provider uses multiple exit addresses, add all of them as separate CIDR ranges.

**Does the allowlist apply to webhook deliveries?** No. Quillstack sends webhook events from its own IP addresses, and those are not restricted by your allowlist. The allowlist only affects incoming requests to the API from your servers.

**What happens if I exceed 20 ranges?** The form rejects additional ranges and displays an error. If you need more than 20, consolidate smaller ranges into larger CIDR blocks or contact support to discuss your use case.
