Every error response from the Quillstack API includes a structured error object with a code field that identifies the specific problem. This reference lists all error codes from QS-1001 to QS-1099, explains what each one means, and describes how to resolve it.

## Before you start

All error responses follow the same JSON structure and include an HTTP status code. The error object contains three fields: `code` (the QS-nnnn identifier), `message` (a human-readable description), and `request_id` (a unique identifier for the request, useful when contacting support).

```json
{
  "error": {
    "code": "QS-1007",
    "message": "Request validation failed",
    "request_id": "req_abc123xyz",
    "errors": [
      {"field": "page_size", "issue": "must be between 1 and 200"}
    ]
  }
}
```

## Authentication and authorization errors

| Code | HTTP Status | Meaning | Resolution |
|------|-------------|---------|------------|
| QS-1003 | 401 | The request has no Authorization header | Add `Authorization: Bearer qs_live_...` to every request |
| QS-1041 | 401 | The API key is invalid or has been revoked | Create a new API key under Settings > Integrations > API keys |
| QS-1042 | 401 | The API key has expired | Rotate the key before expiry to avoid service interruption |
| QS-1014 | 403 | The request came from an IP address outside the workspace's `api.ip_allowlist` (Business only) | Add the caller's CIDR range under Settings > Security > API access |
| QS-1013 | 404 | The resource does not exist or the key's workspace cannot access it | Verify the resource ID and that your API key belongs to the correct workspace |

Error QS-1003 means the request has no Authorization header. Error QS-1041 means the API key is invalid or has been revoked. Error QS-1042 means the API key has expired.

## Validation and request errors

| Code | HTTP Status | Meaning | Resolution |
|------|-------------|---------|------------|
| QS-1007 | 400 | The request body failed validation | Check the `errors` array in the response; each entry identifies an invalid field |
| QS-1029 | 429 | Rate limit exceeded | Wait for the seconds specified in the `Retry-After` header before retrying |

Error QS-1007 means the request body failed validation and the response field `errors` lists each invalid field. When the rate limit is exceeded the API returns HTTP 429 with error code QS-1029 and a Retry-After header giving the wait in seconds.

## Workspace state errors

| Code | HTTP Status | Meaning | Resolution |
|------|-------------|---------|------------|
| QS-1050 | 403 | The workspace is in read-only mode | Update the payment method to restore full access; see Settings > Billing |

Error QS-1050 means the workspace is in read-only mode, so write requests are rejected. This happens when payments fail and all automatic retries are exhausted.

## Integration errors

| Code | HTTP Status | Meaning | Resolution |
|------|-------------|---------|------------|
| QS-1061 | 400 | The webhook endpoint was disabled after repeated failed deliveries | Re-enable the endpoint under Settings > Integrations > Webhooks after fixing the delivery issue |
| QS-1015 | 409 | An export is already running for this workspace | Wait for the running export to finish (up to 24 hours), then start the new one |
| QS-1077 | 500 | An export job failed | Start a new export; if the issue persists, contact support with the request_id |

Error QS-1061 means the webhook endpoint was disabled after repeated failed deliveries and must be re-enabled under Settings > Integrations > Webhooks. Error QS-1077 means an export job failed and a new export must be started.

## Server errors

| Code | HTTP Status | Meaning | Resolution |
|------|-------------|---------|------------|
| QS-1099 | 500 | Internal server error | Retry after 60 seconds; if the error persists, contact support and quote the request_id |

Error QS-1099 is an internal server error; retry after 60 seconds and quote the request_id from the response when contacting support. This error indicates a problem on Quillstack's side, not with your request.

## Steps

### Handle errors in your integration

1. Parse the JSON error response and extract the `code` field.
2. For validation errors (QS-1007), inspect the `errors` array and correct each invalid field before retrying.
3. For rate limit errors (QS-1029), read the `Retry-After` header and wait that many seconds before sending another request.
4. For authentication errors (QS-1003, QS-1041, QS-1042), verify your API key is valid and not expired.
5. For server errors (QS-1099), implement exponential backoff: wait 60 seconds, then retry; if it fails again, wait 120 seconds, and so on.
6. Log the `request_id` for every error; support will ask for it when troubleshooting.

## Troubleshooting

**I am getting QS-1029 constantly.** You are exceeding the rate limit of 600 requests per minute per API key. Implement request throttling in your client or batch multiple operations into fewer API calls.

**QS-1042 appeared suddenly.** Your API key expired. Keys expire after 30 days on Free, 90 days on Team, and 365 days on Business. Rotate keys before they expire to avoid downtime.

**QS-1050 is blocking all writes.** Your workspace entered read-only mode after a payment failure. Update the payment method under Settings > Billing, and full access is restored immediately.
