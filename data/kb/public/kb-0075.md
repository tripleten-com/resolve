This article lists known issues in Quillstack and how to work around them. We update it as issues are identified and resolved. If you encounter a problem not listed here, check the status page at status.quillstack.com or contact support.

## Before you start

Known issues are problems we have confirmed and are working to fix. They differ from bugs you might encounter individually: these affect multiple customers and have documented workarounds where possible. The list below is current as of the last update to this article. For real-time incident updates, subscribe to status notifications at status.quillstack.com.

## Current known issues

### Webhook endpoints disabled after failed deliveries (QS-1061)

Error QS-1061 means the webhook endpoint was disabled after repeated failed deliveries and must be re-enabled under Settings > Integrations > Webhooks. This happens when your endpoint does not return a 2xx response for five consecutive delivery attempts over 24 hours.

**Workaround:** Fix the issue causing your endpoint to fail, then navigate to Settings > Integrations > Webhooks, locate the disabled endpoint, and click Enable. Quillstack will resume sending events immediately. If you continue to see failures, verify that your endpoint responds with HTTP 200 or 204 and completes within 10 seconds.

### Internal server errors (QS-1099)

Error QS-1099 is an internal server error; retry after 60 seconds and quote the request_id from the response when contacting support. This error indicates a temporary problem on the Quillstack side, not an issue with your request.

**Workaround:** Implement exponential backoff in your API client. Wait 60 seconds, then retry the request. If the error persists after three retries, contact support and include the request_id from the error response. Our team can investigate the specific cause and prioritize a fix if the issue affects multiple requests.

Example error response:

```json
{
  "error": {
    "code": "QS-1099",
    "message": "Internal server error",
    "request_id": "req_8x4k2mP9vL"
  }
}
```

### Mobile app billing settings unavailable

The mobile app requires iOS 16 or later or Android 11 or later; offline edits sync on reconnect with conflicts resolved as last write wins; billing settings cannot be changed from the mobile app, only at app.quillstack.com. You can view your current plan and seat count in the mobile app under Settings > Workspace, but any billing changes must be made through the web interface.

**Workaround:** Open app.quillstack.com in a browser on your mobile device or switch to a desktop to update payment methods, add or remove seats, or change your plan. Changes made on the web apply immediately to the mobile app after your next sync.

### Slow import from Confluence for large spaces

Imports from Confluence spaces larger than 500 pages can take significantly longer than the estimates shown in the import wizard. The process may appear stalled but is still running in the background.

**Workaround:** Start the import and wait up to 24 hours before assuming it has failed. You will receive an email when the import completes. If you do not receive confirmation after 24 hours, check Settings > Imports for status. Only one import can run per workspace at a time, so cancel any stalled import before starting a new one.

### Page embeds do not render in email notifications

When a page contains an embed (such as a Figma design or Google Doc), the email notification shows a placeholder link instead of rendering the embed inline. The embed displays correctly when you open the page in the web or mobile app.

**Workaround:** Click through to the page in Quillstack to view embedded content. Alternatively, configure your email digest to send only summaries under Settings > Notifications > Digest, which reduces the need to view full content in email.

## Troubleshooting

If your issue is not listed above, follow these steps:

1. Check status.quillstack.com for ongoing incidents that might affect your workspace.
2. Review the error code reference in the API documentation or in the article for your specific error.
3. Try the same action in a different browser or clear your browser cache.
4. If the issue persists, contact support with a detailed description, including timestamps, error codes, and screenshots.
