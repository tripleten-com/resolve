You can import Markdown files into Quillstack by uploading a .zip archive that contains your .md files and any linked images or attachments. The importer creates a page for each Markdown file and preserves your folder structure as nested pages. This is useful when you are migrating documentation from a static site generator, a local Markdown editor, or any system that exports to Markdown.

## Before you start

Only workspace Admins and Owners can start an import. You must be on any plan—Free, Team, or Business all support Markdown imports—but only one import can run per workspace at a time. If another import is in progress, wait for it to finish before starting a new one.

The .zip archive may be at most 2 GB. If your archive is larger, split it into multiple smaller archives and import them one at a time. The importer accepts .md and .markdown file extensions and supports CommonMark syntax, including fenced code blocks, tables, and task lists. Images and other attachments must be referenced with relative paths in your Markdown files, and those files must exist inside the .zip archive.

## Steps

1. Prepare your .zip archive with all .md files and any images or attachments they reference. Organize files into folders if you want them to appear as nested pages in Quillstack.
2. Sign in to Quillstack at app.quillstack.com and open the workspace where you want to import the files.
3. Go to **Settings > Import** and choose **Markdown (.zip)** from the list of importers.
4. Click **Choose file** and select your .zip archive, then click **Start import**.
5. The import runs in the background. You will receive an email when it completes, usually within a few minutes for small archives or up to an hour for archives close to 2 GB.
6. After the import finishes, navigate to the Pages section to review your imported content. Each Markdown file becomes a page, and folders become parent pages with nested children.

The importer does not modify your original archive, so you can retry if something goes wrong.

## How it works

The Markdown importer walks through every .md file in your archive and converts it to a Quillstack page. Folder structure is preserved: if your archive has a folder called `guides` with a file `setup.md` inside, the importer creates a parent page named "guides" and a child page named "setup" beneath it. Front matter (YAML or TOML metadata at the top of a Markdown file) is ignored.

Images and attachments are uploaded if they are referenced with relative paths like `./images/screenshot.png` or `../assets/diagram.pdf` and those files exist in the archive. Absolute URLs and external links are left as-is. The importer matches file references case-insensitively, so `Image.PNG` in Markdown will find `image.png` in the archive.

The following table shows how Markdown syntax maps to Quillstack features:

| Markdown                     | Quillstack result              |
|------------------------------|--------------------------------|
| `# Heading`                  | Heading block                  |
| `**bold**` and `*italic*`    | Inline formatting              |
| `` `code` ``                 | Inline code                    |
| Fenced code block            | Code block with syntax highlighting |
| `- [ ] task`                 | Task list (checkboxes)         |
| Tables                       | Table block                    |
| `![alt](image.png)`          | Embedded image (uploaded)      |
| `[link](page.md)`            | Link (converted to internal page link if page.md was also imported) |

Links between Markdown files are converted to internal page links when both the source and target files are part of the same import. For example, if `overview.md` links to `details.md` and both are in the archive, the imported "overview" page will link to the imported "details" page.

## Troubleshooting

**The import failed immediately.** Check that your .zip archive is not corrupted and is smaller than 2 GB. Try unzipping it on your computer first to confirm it is valid. If the archive contains files with names that are not valid UTF-8, rename them before re-archiving.

**Some images did not upload.** Verify that the image paths in your Markdown match the actual file locations in the archive, including folder names. The importer only uploads files that are explicitly referenced in at least one .md file. Unreferenced files in the archive are ignored.

**An import is stuck.** Imports for large archives can take up to an hour. If more than two hours have passed with no email, contact support and include the workspace name and the approximate size of your archive.
