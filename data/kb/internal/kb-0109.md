This page lists standard reply templates (macros) for common support scenarios. Use these to maintain consistency, meet response time targets, and avoid repeating canonical facts incorrectly. Always personalize the greeting and adjust tone to match the customer's message, but keep the core facts unchanged.

## Before you start

Every reply must include your signature block with your name and the support tier reminder. Check the workspace plan in the admin console before sending a macro that references plan limits or features. First-response targets are 3 business days on Free, 1 business day on Team, and 4 business hours on Business.

Macros are stored in the helpdesk under Settings > Macros. To insert a macro, type `#macro-name` in the reply box or use the Insert menu. The helpdesk replaces placeholders like `{{customer_name}}` and `{{workspace_id}}` automatically.

## Steps

### Send a password reset macro

Use macro `password-reset-sent` when a customer reports they cannot sign in and you have manually triggered a reset:

```
Hi {{customer_name}},

I've sent a password reset link to {{email}}. The link expires after 60 minutes and can be used only once. If you don't see it, check your spam folder.

If the link has expired, go to https://app.quillstack.com/reset and request a new one.

Let me know if you're still having trouble signing in.
```

Use macro `account-locked` if the helpdesk shows 5 failed sign-in attempts in the last 15 minutes:

```
Your account was locked after 5 failed sign-in attempts. The lock will lift automatically in 15 minutes from the last attempt.

Once the lock expires, request a password reset at https://app.quillstack.com/reset if you've forgotten your password.
```

### Send an API key expiry macro

Use macro `api-key-expired` when the customer reports error QS-1042:

```
Error QS-1042 means the API key has expired. API keys expire after 30 days on Free, 90 days on Team, and 365 days on Business.

You'll need to create a new key and update your application:

1. Go to Settings > Integrations > API keys
2. Click Create key and copy the key immediately (it's shown only once)
3. Replace the expired key in your application
4. Revoke the old key under the same settings page

See our guide: [Rotate an API key](kb-0045)
```

### Send a billing escalation macro

Use macro `billing-escalation` when the customer asks about a refund, chargeback, or disputed charge and you are not an Admin or Owner of their workspace:

```
I'll need to escalate this to our billing team for review. They'll reply within 3 business days.

For security, we discuss billing details only with the Owner or Admins of the workspace. If you're not listed as one of those roles, please have an Owner or Admin contact us directly from their account email.
```

Use macro `refund-policy` for general refund questions before escalating:

```
Refunds are only possible within 14 days of a charge. Every refund request is reviewed by the billing team, which replies within 3 business days. We don't issue refunds automatically.

If you'd like to request a review, reply with:
- The invoice number (format: INV-YYYYMM-NNNNN)
- The reason for the refund request

I'll forward this to the billing team.
```

### Send a duplicate charge macro

Use macro `duplicate-charge` when the same amount was charged twice within 24 hours:

```
I see two charges for {{amount}} on {{date}}. If the same card was charged the same amount twice within 24 hours, the second charge is likely a duplicate.

I've flagged this for the billing team to review. After confirmation, they'll reverse the duplicate charge within 5 business days. You'll receive an email when the reversal is processed.

The invoice for the correct charge is {{invoice_number}}.
```

## Troubleshooting

| Problem | Solution |
|---------|----------|
| Macro inserts placeholder text like `{{customer_name}}` instead of the real value | The helpdesk field is missing or the customer record is incomplete. Fill in the field manually in the ticket or edit the customer record in the admin console. |
| Customer replies that the macro answer did not help | Do not send another macro. Write a personalized reply that asks for specific details (error message, screenshot, workspace ID, steps they tried). |
| Macro references the wrong plan | Check the workspace plan in the admin console at admin.quillstack.internal before sending. Edit the macro text to match the customer's actual plan. |
| Customer is angry or escalating | Do not use a macro. Write a personal reply, acknowledge their frustration, and loop in #support-escalations on Slack if you need help. |

If a macro contains outdated information (wrong expiry time, wrong limit, wrong error code), update it immediately in the helpdesk and post in #support-updates so the team knows. Never send a macro you know is incorrect.
